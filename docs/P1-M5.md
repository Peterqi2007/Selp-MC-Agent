### 5.9 M5-CU 前置门实现（离线，2026-10-18）

按要求"先修真机接线、不换采集路径、不跑真机 act"：本轮只交付**离线门**与**只读几何来源**，
没有执行任何真机 act，也没有改采集后端。

| 模块 | 职责 | 关键拒绝码 |
| --- | --- | --- |
| `windowPolicy.check()` | act 门 | `cu-unproven` `outside-window` `outside-bounds` `bounds-required` `coordinates-required` |
| `windowPolicy.checkObserve()` | 只读观测门 | `observe-window-required` `not-candidate-window` `candidate-not-unique` `interaction-not-allowed` `kind-not-allowed` |
| `windowPolicy.verify()` | F1 证据门 | `screenshot-required` `bounds-source-invalid` `window-mismatch` `bounds-invalid` |
| `guard.act()` / `observe()` | 策略 → 执行器唯一路径 | 拒绝时 `executed:false` 且执行器不被调用 |
| `preflight.act()` / `observe()` / `resolveRect()` | 宿主适配层入口 | 透传；`resolveRect` 先校验窗口再取几何 |
| `windowRect.resolveRect()` | 几何来源链 | helper → win32/dwm → `rect-unavailable` |

设计要点：

1. **读与做分两门。** `verify()` 之前 act 全部 `cu-unproven`；只读观测走 `checkObserve()`，
   只放行唯一候选窗口。截图**作为 act** 仍被拒，**作为观测**才放行——不让一个入口模糊两种风险。
2. **观测必须带显式 `windowId`**，且不得携带 `x`/`y`/`key`/`button`/`text` 等字段
   （`interaction-not-allowed`）。
3. **`verify()` 不再接受占位证据。** 旧用例里 `evidence: 'F1 pending'` 这种写法现在会被拒；
   仓库内两处旧调用已改为真实证据对象，仍保持原测试意图。
4. **rect 不能来自像素。** `screenshot-size` 不是合法来源，`normalizeRect()` 与 `verify()`
   双重拒绝；全来源失败返回 `rect-unavailable` 且**不带 rect 字段**，调用方只能写"bounds 待补"。
5. **Win32 探针只读**：只调 `GetWindowRect` / `DwmGetWindowAttribute` / `IsIconic`；
   契约测试断言脚本内不出现 `PrintWindow|BitBlt|SendInput|keybd_event|mouse_event|CopyFromScreen`。
6. **几何查询也受窗口门约束**：`resolveRect()` 先过 `checkObserve()`，非候选窗口的 rect
   根本不会被查询（测试用 spy provider 断言未被调用）。

测试：`p1:contract:test` 新增第 42 组 20 条（观测门、verify 证据门、rect 来源链、只读探针、
非候选窗口不查几何），当前总计 **206/206**；`plan:audit --stage p1` **105/105**；
`p1:verify` **11/11** 套件（含 P0 回归；`--fast` 10/10）。

**诚实边界**：这些模块目前**没有被打包的 DSH 插件调用**。`resources/app.asar` 不可改，
所以真机 `computer_use_*` 仍只受 helper 自身授权约束；F1 判定不变（未通过）。
本轮交付的是"**门可用且可测**"，不是"门已生效"。接线点就是 `CuPreflight`：
宿主适配层把 `computer_use_act` / `computer_use_state` 改走它，才谈得上真机限窗。

## 6. 只读 F1 观察例外（明文，**仅 CU 可选路径**）

为能测量 F1，保留一个**有限、可审计**的只读例外。它不等于 `verify()`，也不授予任何 act：

1. **仅唯一候选 Minecraft 窗口**：候选集合必须恰好一个窗口，否则 `candidate-not-unique` 拒绝。
2. **显式 `windowId`**：观测请求必须指名窗口，缺省即拒（`observe-window-required`）；
   非候选窗口即拒（`not-candidate-window`）。
3. **无 act**：请求携带 `x`/`y`/`button`/`key`/`text` 任一字段即拒（`interaction-not-allowed`）。
4. **截图只用于两件事**：确定 bounds 的佐证、验证限窗是否成立。截图尺寸**不得**反推 x/y。
5. **不等于 verify**：观测成功不改变 `policy.verified`；`verify()` 仍需成功截图 + 真实几何来源的 bounds。

该例外默认开启，可用 `new WindowPolicy({ readOnlyObservation: false })` 关闭
（关闭后观测返回 `observation-disabled`）。

## 7. 口径变更：M5 改走进程内输入层（2026-10-29 定）

### 7.1 为什么换

原方案（Q5/§1.8.3）是「复用 `dsh-computer-use` + 提示词限窗 + F1 证明」。实测与代码审计证明这条路在 P1 内**不可收敛**：

| 阻断点 | 事实 | 我们能改吗 |
| --- | --- | --- |
| WGC 取不到帧 | 全屏 429×270 / 窗口化 696×417，两次均 `截图未产出` + `Declared image type does not match its bytes` | 否（helper 侧，且日志不可得） |
| 策略接不进真机 | `WindowPolicy`/`ComputerUseGuard` 在 `src/` 内只被自己引用；`resources/app.asar` 只读 | 否 |
| 真机只读口径分裂 | 已授权应用为空时 `computer_use_state` 仍被放行（§5.5） | 否 |

三项都不属于本项目可控范围，继续投入只会重复得到同一个失败。

### 7.2 新方案：进程内输入层（in-process input layer）

Minecraft mod 在**游戏进程内**合成输入并抓图，经既有 HTTP 通道交给 Node；Node 仍是唯一身体执行权、
键鼠台账与结果验证的持有者。

| 能力 | 实现（mod 侧） | 相比 CU |
| --- | --- | --- |
| 按键（含长按） | `KeyMapping.setDown(true/false)` + 每 tick 维持，暴露 `body_key` / `body_hold(ms)` | 不需要窗口焦点，不需要 `SendInput` |
| 视角 | 直接写 `player.setYRot/setXRot`（限速率），暴露 `body_look` | 不需要像素坐标换算 |
| GUI 点击 | 容器槽位 API（复用现有 `click <slot>`），每次重读 `menu` 再点 | 不依赖 bounds/分辨率/缩放 |
| 视觉观察 | 帧缓冲 `Screenshot`/`glReadPixels` → JPEG → HTTP（事件驱动 + 按需） | 绕开 WGC 与 OpenGL 合成问题 |
| 状态观察 | 既有 `/state` 结构化字段 + `menu` 槽位快照 | 天然新鲜、可 diff |

**它不是能力降级**：原方案的限窗约束靠「外部插件 + 提示词」保证，新方案的约束是**结构性的**——
输入层只调用游戏内 API，物理上不可能触达游戏外的任何窗口或进程。代价是它**永远做不了游戏外的事**
（启动器/登录/其他程序），而 M5 的命题本来就把窗外操作定义为无意义。

### 7.3 闸门替换：F1 → F1'

| 闸门 | 断言 | 证据方式 |
| --- | --- | --- |
| **F1'a 结构性不可出界** | 输入/截图只走游戏内 API 与本进程帧缓冲；仓库内不出现 `SendInput` / `keybd_event` / `mouse_event` / `BitBlt` / `PrintWindow` | 契约测试对 mod 与 Node 源码做字符串断言（与 §5.9 第 5 条同款写法）+ 代码评审 |
| **F1'b 键鼠台账** | 任意时刻按下集合可枚举；游戏内暂停（PauseScreen）、死亡、断连、急停、取消、任务结束、进程退出时**全部强制释放**；单次长按有上限 | `InputLedger` 契约测试 + 真机故障注入（暂停/死亡/取消/断连各 1 次，结束后断言台账为空） |

F1' 不通过则**实现不得合并**；这里没有"标 N/A 放弃"的出口——因为不再依赖任何外部工具。

### 7.4 验收重定义（命题不变，证据重记）

| ID | 原口径 | 新口径（2026-10-29） |
| --- | --- | --- |
| F1 | CU 能否限窗；不通过则 A21/A22 标 N/A | **作废**，由 F1'a/F1'b 取代；A21/A22 **不标 N/A** |
| A21 | 2 类真实 GUI ×≥3；插失焦/界面/库存变化/长按；每步新鲜观察；不点旧坐标；产出可验证；限游戏窗口 | **命题不变**。故障注入改为：游戏内暂停界面、GUI 被外部关闭、库存变化、长按（挖掘/攻击各 1 次）；"限窗"由 F1'a 结构性保证 |
| A22 | GUI 中反射/急停清理按键与执行权；稳定流程复用后模型调用/截图 token 下降且效果一致 | **命题不变**，判定量化为 `InputLedger` 归零 + 复用前后 token/调用数差值，不预设节省比例 |
| M5.3 | GUI 场景复核 A07/A08/A12 | 不变 |

### 7.5 实现清单（后续按此执行）

**已有基础（不必从零做）**：mod 侧已能注入移动键（`mc.options.keyUp/setDown` 等，
`mod-client/src/main/java/dev/agentclient/ClientActions.java:2151`），HTTP 已暴露
`moveto/goto`、`dig/mine`（内部持续按住）、`attack`、`menu`、`click`（槽位）
（`ControlHttpServer.java:429-556`）。所以新路径缺的不是"注入能力"，而是
**显式按键语义 + 台账 + 截图 + 结构断言**。

1. **mod 输入层**：`body_key(action, down|up)`、`body_hold(action, ms, capMs)`、`body_look(yaw, pitch, rateDegPerTick)`、`body_click_slot(slot, button, mode)`（复用容器原语）、`body_screenshot(scale, quality)`；全部走既有 HTTP 与执行权门。
2. **按键台账（Node 侧）**：`InputLedger` 记账 → 反射/急停/取消/死亡/断连/退出统一 `releaseAll()`；与 `TaskSlot` 单执行者绑定；台账非空时拒绝新任务。**接入点**：`src/core/holds.js` 的 `Holds.hold()`（dead/paused/owner-stop/task 四种 hold）每次进入都立即 `releaseAll()`，这是现成的"必须放手"信号源，不要另起一套布尔量。
3. **观察**：帧缓冲截图（事件驱动：提案接受、卡住/失败、结构遇到、按需工具）+ `menu` 槽位快照 + 既有 `/state`。
4. **安全**：`inputPolicy`（无执行权拒绝、越界动作拒绝、长按超限拒绝）+ F1'a 字符串断言测试 + 台账归零测试。
5. **真机**：A21（2 类 GUI ×≥3，含四类故障注入）、A22（反射/急停 + 复用降本）、M5.3（GUI 场景 A07/A08/A12）。
6. **文档回填**：每项执行后按 P1 规则记录版本/账号/配置/证据路径；未执行项保持"未执行"。
