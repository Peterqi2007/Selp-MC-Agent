## 0. 2026-10-18 接线（本次新增）

此前 `ConversationState` 只在测试里被完整使用，live 只走到 `reply()` 的 opt-in 守卫；
普通多人聊天没有“参与/沉默”入口，pending proposal 也没有聊天回答入口。本次补上：

| 能力 | 实现 | 说明 |
| --- | --- | --- |
| **普通聊天参与/沉默** | `src/chat/chatParticipation.js` | 只处理未点名普通聊天；模型输出 `{respond:true,text}` 或 `{respond:false}`；没有 action 工具，畸形输出按沉默 |
| **对话上下文** | 同上 | `Recent chat` 最多 15 行（玩家行 + `我:` 自己的回复）；自己的回复在**发送成功后直接写入**，**不从聊天日志回读**（避免操作员同账号发言被当成 Agent 发言） |
| **窗口持久化** | `ChatParticipation.toJSON/restore` + `sessionState` | 最近窗口随 `runtime/p1-state.json` 保存（`chatParticipation`）；重启只恢复为上下文，**不重放消息、不自动调用模型** |
| **长期聊天记忆** | `src/chat/playerChatLog.js` + `src/memory/chatMemory.js` | **所有非 `!` 指令的玩家消息**写入 ChatMemory（含 `@`/对话/普通聊天）；`!` 命令与 Agent 自己的账号不写；`LanguageDialogue` 用 `attachReply` 只补 assistant，避免重复 user 条目 |
| **请求生命周期** | 同上 + `ConversationState` | `rememberIncoming` 去重 → `beginRequest(requestId)` → `reply({conversation:true,requestId})`；旧请求的迟到回复被 `stale-request` 拒绝 |
| **提案聊天回答** | `src/chat/proposalChat.js` | 仅当提案 pending 时，独立 `好/可以/yes` 或 `不/不要/no` 才调用既有 `acceptProposal`/`rejectProposal`；模糊回复不视为同意 |
| **发送者归因** | `src/index.js` `onOther` | 解析 `<player>`；不再把空/服务器提示当聊天；A11 的 `noteChat` 现在带 from |
| **opt-in 配置** | `config/agent.json` | `chat.participate=false`、`chat.proposalChat=false`；默认行为仍是“只在被点名/命令时响应” |
| **测试** | `scripts/p1-m6-test.js` | **24/24**：发言/沉默/畸形、上下文（15 行上限、自己的回复入上下文、沉默/被丢弃不入上下文、窗口保存/恢复）、长期记忆写入（非 `!` 玩家消息、命令/自己账号跳过）、去重、过期请求、重复回复、提案 yes/no/模糊/无 pending；DialogueRouter（harness/planner-first/handoff/绑定重试）、`/say`、面板路由 |

### 0.2 2026-10-22 自然语言对话路由（DialogueRouter）

`@角色 …` 以前直接进 `LlmCore.handle`，所以即使 `chat.actionBrain="harness"`，任务请求也只到本地
P0 intent planner。现在 `src/chat/dialogueRouter.js` 按 `chat.actionBrain` 统一路由：

| 模式 | 行为 |
| --- | --- |
| `harness`（默认） | 所有 `@` 自然语言 → DSH 动作脑；不调用 `LlmCore.handle`，失败也不本地执行 |
| `planner-first` | 本地理解的任务本地执行；`understood-nothing` → 原文交 DSH（`llm.handle` 新增 `onUnresolved:'defer'`） |
| `planner` | 旧行为（回滚） |

- 转发 envelope：`[MINECRAFT PLAYER REQUEST]` + source/speaker/agentPosition/text/instruction；
  插件 `/message` 送入 live 对话。
- `chat.harnessAgentId`：可选预绑定；`no-live-agent` 时用该 id `POST /bind` 重试一次。
- 动作脑发言：插件 `mc_say` → Node `POST /say` → `ctx.reply()`（sanitize/截断/回环过滤）。
- 面板 `@…` 走同一 router；`!` 命令（含 `!goal`）仍走本地命令表。
- 测试：`p1:m6:test` **24/24**；插件 `plugin-goal-test` 含 `mc_say`；`/ui/state.dialogue` 显示最近路由。

**真机（2026-10-22，真实 Forge 客户端）**：
- 面板 `@大肥鱼 现在游戏里几点？用 mc_state(fields=[time])…` → `/ui/state.dialogue` =

## 2. 设计边界

- **默认关闭**：普通聊天参与会改变“agent 是否插话”的产品行为；`participate/proposalChat`
  默认 false，客户端窗口显式打开。
- **模型只说话**：`ChatParticipation` 没有 brain/body/动作工具；提示词要求 JSON，只有
  `respond/text` 被读取；畸形输出、超时、模型不可用都是沉默。
- **不按名字过滤**：触发/前缀仍在 ChatListener；参与决策由模型基于内容与上下文，不用
  名字关键词硬编码。
- **单操作员模拟**：A23/A24 若只有你一个玩家，证据必须标注“单操作员模拟，非真实多人”；
  不能把单人语料外推为真实多人社交结论。
- **提案回答是确定性的**：`ProposalChat` 只接受独立 yes/no；它不做执行，也不把模糊回复
  当同意。动作脑自主提案的措辞已由 `LanguageBrain.expressProposal` 承担（只说话；
  模型不可用时模板兜底），A25 的四条真机路径仍需验证。
