## 5. Voyager 式自动课程（automatic curriculum）

### 5.1 参考

- `refs/Voyager/voyager/agents/curriculum.py`：维护 `completed_tasks` / `failed_tasks`，
  把当前观察 + 已完成 + 太难的失败任务交给模型，要求「不要太难、要新颖、必要时才重复」。
- `refs/Voyager/voyager/prompts/curriculum.txt`：任务格式（单句）、mentor 语气、避免需要视觉确认的
  建筑/放置类任务。

### 5.2 实现（`src/planner/curriculum.js`）

| 能力 | 内容 |
| --- | --- |
| 难度表 | 按命令表 type + `args.block/item` + 数量分 1–5 级（`chop`1、`craft`2、`mine iron`2、`mine diamond`4、`shoot`3…） |
| 难度带 | `level = 1 + floor(completed / bandStep)`，默认每 2 个完成 +1，封顶 4 |
| 历史 | `completed`/`failed` 列表，原子写 `runtime/curriculum.json`（temp+rename），重启恢复 |
| 上下文 | `describe()` 输出 Voyager 形状的块：Completed / Failed / 当前 band / 上次完成 / focus / 5 条规则 |
| 校验 | `validate(candidate)`：低于 band → `difficulty-below-curriculum`（模型可重试）；连续 `maxRejections` 次后 `curriculum-relaxed` 放行，**不死锁** |
| 闭环 | 执行 goal `complete` → 记完成并升 band；`blocked` → 记失败（太难的先避开） |

### 5.3 接线

- `AutonomousProposalCoordinator.startPrep()` 把 `curriculum.describe()` 追加进 proposal-prep goal；
  插件 `proposalPrepObjective` 的 `CONTEXT: ${goal}` 原样带给动作脑（**不需要改插件**）。
- `Brain.proposeFromHarness()` 在 autonomous 分支先 `validate()`；拒绝时返回 required/actual/level
  与可读 detail，模型可改提案。
- `GET /curriculum` 与 `/ui/state.curriculum` 暴露 band/历史/最近校验（只读）。
- 配置：`planner.autonomousProposals.curriculum`（enabled/file/bandStep/maxLevel/maxRejections/historyLimit）。

### 5.4 测试

`p1:curriculum:test` **8/8**：难度表、band 增长与封顶、拒绝→重试→放宽、上下文内容、
持久化恢复、prep goal 携带上下文、执行 goal 结算写入、接线源码断言。

### 5.5 限制

- 难度表是启发式，不是模型判定；未知类型按 1 级。
- 真机已验证「prep 上下文 + 提案 validate + 两次完成 → level 2 → 下一次 prep band 2/4」；
  **未验证**「level 2 的模型提案内容本身更难」——第二次 prep 以 `goal-ended-without-proposal`
  结束（模型没提案），因此只证明了 band/校验链路，不是模型选择难度。
- 「automatic curriculum」是**提示 + 校验**，不是自动生成任务文本；任务仍由动作脑提出。
  如果模型持续无视 band，`maxRejections` 后会放行——这是有意的（宁可略简单，不可卡死）。

## 9. 自卫反射状态可见性（2026-10-31）

### 9.1 问题

自卫反射（`behaviour.autoFight`）是 Node 快循环，不改模组状态，也不经动作脑批准。它可能：

- 在动作脑执行任务时自己攻击附近敌意生物；
- 因受伤/低血抢占当前任务，导致动作脑看到“任务莫名中断”；
- 让动作脑把反射攻击误当成自己刚下发的指令，或反过来怀疑玩家在控制。

动作脑此前只能从 `hostiles` 看到“有敌人”，看不到“Node 会不会自己打”，于是无法正确解释结果。

### 9.2 实现

- 新增 `src/world/selfDefense.js`：唯一状态源，严格复用 `brain.js:693` 的真值判断（`autoFight === true`），
  输出 `enabled / engaging / engageHealthThreshold / engageRadiusXZ / engageRadiusY /
  fleeHealthThreshold / note`。
- `ObservationCache` 新增 `staticFields` 机制：Node 本地派生字段不触发 `/state` 刷新、不会因
  客户端不可达而被误标 stale；`selfDefense` 作为静态字段返回 `source:"runtime"`。
- 观测层：`selfDefense` 可按名查询，`threat`/`combat` 组自动包含它；`/ui/state.selfDefense`
  供面板与轻量 `mc_observe` 读取。
- DSH 插件：`FULL_OBSERVATION_FIELDS` 增加 `selfDefense`；`mc_observe` 短摘要带
  `selfDefense`；`mc_state`/`mc_observe` 描述明确“enabled 时 Node 可能自行攻击并抢占任务，

### 9.4 限制

- `engaging` 只反映当前 `Brain._reflexFight`，不保留每次反射攻击的历史；动作脑可通过
  `selfDefense.enabled` + `hostiles` 解释，但不能回放“哪一次是反射”。
- `autoFight` 目前只有配置开关，没有运行时 `!` 命令；状态会随配置值变化，不是实时切换。
- 该字段是 Node 事实，不是模组状态；`/state` 原始响应（8899）仍不含它，`mc_state` 走
  `/observe` 才有。
