## 1. 本批交付（M1a + M1b + M1c）

| 交付 | 位置 | 说明 |
| --- | --- | --- |
| **事件汇聚 `TaskEvents`** | `src/core/taskEvents.js` | 单调 `seq`、`eventId` 幂等、环形重放 `since()`、订阅者；无 I/O，订阅者抛错不影响生产者 |
| **身份字段** | `src/tasks/task.js` | `taskId / requestId / planId / stepId` 为可选字段，旧调用不变；`attemptId` 由执行器按 `name#retries` 生成 |
| **统一出口扩展** | `src/core/taskSlot.js` | `slot.publish()` 同时写事件 hub 与旧监听表；planner 任务与 hub 作业共用 |
| **计划单一写者** | `src/core/planStore.js` | 新计划 v1；重规划 `baseVersion` 必须等于当前版本，否则 `stale`；**已完成步骤不被重规划重开** |
| **同端口 SSE** | `src/web/eventStream.js` + `statusServer.js` 的 `GET /events` | `Last-Event-ID` 重放、心跳、断开清理；`Authorization: Bearer` 或 `?token=`；**不另开端口**（Q1） |
| **鉴权配置** | `config/agent.json` → `web.eventsToken` | 空 = 仅本机；非空则拒绝无 token 的流（401） |
| **Capability 表（M1b）** | `src/core/capabilities.js` | `crafting/deposit/hunting` 读 body 标志，`light/shelter` 要宿主；支持与否和"缺材料"分开，跳过带原因 |
| **TaskResult 六态（M1b）** | `src/tasks/task.js` | `succeeded/partial/blocked/failed/cancelled/unknown`；`ok` 保留兼容；取消/无路/未确认分别归类 |
| **Progress 值域（M1b）** | `src/tasks/mineOre.js` | `progress()` 改为稳定字符串 `mined/skipped`，P3 关闭；B1 停牌对矿石路径生效 |
| **父计划执行（M1c）** | `src/core/planRunner.js` | 子步骤走内部 `runTask`，**不**再 `TaskHub.submit`；完成步骤写回 PlanStore；`cancel()` 在步间生效 |
| **回合生命周期（M1c）** | `src/core/turnLifecycle.js` | 一回合一次：`running → waiting → resumable → running`；重复/不匹配事件拒绝；取消后迟到事件无效 |
| **审计** | `plan:audit --stage p1` | 新增 6 条（事件 hub/SSE、计划单一写者、Capability、六态、PlanRunner、TurnLifecycle）；p1 共 **40** 条 |
| **离线测试** | `npm run p1:contract:test` | 20/20：事件/计划/身份、Capability、六态、SSE、父计划执行/跳过/停止/取消、回合恢复与取消 |
